# Effect AI adapters: plan

`@shpitdev/foundry-effect-ai` gives Effect AI programs the Foundry coverage `@shpitdev/foundry-ai` gives the Vercel AI SDK: OpenAI, Anthropic, Google and xAI models through Foundry's LLM proxy, addressed by catalog alias or RID. It ships as one package whose only peer dependency is `effect`, and an application that uses one vendor bundles only that vendor's code.

Release candidates publish to npm's `next` tag as phases land; phase 8 cuts the first stable release. Phases 1 and 2 are done: `FoundryClient`, `OpenAiDecisionModel` and `OpenAiLanguageModel` work. Every other public function is still a stub that dies with a pointer to this file.

## Decisions

| Topic              | Decision                                                                                                                                                                                                                                                                                                                                                                                       | Why                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dependencies       | `effect` ^4.1.4 only. No vendor SDKs, no `@effect/ai-openai` or `@effect/ai-anthropic`.                                                                                                                                                                                                                                                                                                        | Effect 4 ships the AI core (`effect/ai`), HTTP client (`effect/http`) and SSE decoder (`effect/encoding/Sse`). The upstream providers add 22k–77k-line generated schema files, and there is no Effect 4 Google provider.                                 |
| Public surface     | One module per vendor and model kind, imported by subpath: `@shpitdev/foundry-effect-ai/AnthropicLanguageModel`. No root entry, no barrel.                                                                                                                                                                                                                                                     | A barrel would pull every vendor into every bundle. This mirrors upstream Effect's deep-import style.                                                                                                                                                    |
| Module API         | `model(id, config?)` returning `AiModel.Model`, plus `make` and `layer`, matching upstream providers. `config` holds request-wide settings under their wire names (OpenAI: `reasoning`). `withConfigOverride` waits for a cell that needs it.                                                                                                                                                  | Users can swap an upstream provider for ours without restructuring their program.                                                                                                                                                                        |
| Provider namespace | The `providerName` (`foundry-openai`, `foundry-anthropic`, `foundry-google`, `foundry-xai`) is the only key for response metadata and provider options. Never augment the upstream `openai` or `anthropic` keys. Transport errors carry Foundry's `errorName`, `errorInstanceId` and the vendor `code` and `type` under `foundry`.                                                             | Upstream providers augment `DecideResponseMetadata` and the `Response.*Metadata` interfaces under `openai` and `anthropic`; our shapes under the same keys fail typecheck for anyone who installs both.                                                  |
| Transport          | One `FoundryClient` service with two operations, `json` and `sse` (phase 2). It owns the URL, bearer token, attribution and trace headers, and maps HTTP failures to `AiError` in `internal/errors.ts`. A request may add headers, such as `anthropic-version` or `X-Palantir-session-id`. A configured `traceParent` replaces the trace context Effect would propagate from the current span. | Protocol-typed client methods would put every schema into the shared module.                                                                                                                                                                             |
| Wire schemas       | Hand-written `effect/Schema` codecs under `src/internal/<protocol>/`, decoding only the fields we read; unknown stream events are ignored. Requests are plain interfaces.                                                                                                                                                                                                                      | Foundry deviates from vendor specs in small ways (omitted `object`, extra reasoning events), so strict generated schemas fail. Upstream also hand-writes its OpenAI client schemas.                                                                      |
| Vendor quirks      | Request shaping lives in the vendor module: `store: false`, strict function tools, forced reasoning, Anthropic structured-output mode, no eager tool-input streaming.                                                                                                                                                                                                                          | Same rules as `packages/foundry-ai/src/providers`, driven by flags in each vendor's model list.                                                                                                                                                          |
| Streaming          | Every language model implements both `generateText` and `streamText`.                                                                                                                                                                                                                                                                                                                          | `LanguageModel.make` requires both.                                                                                                                                                                                                                      |
| xAI                | `XaiLanguageModel` reuses the Responses codec, passing its xAI dialect as a value.                                                                                                                                                                                                                                                                                                             | Foundry serves Grok through Responses; the AI SDK adapter's `xai-compat.ts` rewrites are unnecessary with lenient decoding. Vendor branches inside `openai-responses/` would be invisible to the tree-shaking check, since both modules own that folder. |
| Build              | `tsc` emits ESM, one file per module, `sideEffects: false`.                                                                                                                                                                                                                                                                                                                                    | Effect 4 is ESM-only; per-file output lets bundlers drop unused modules without a pure-annotation pass.                                                                                                                                                  |
| Model lists        | Each vendor has its own plain list in `src/internal/models/<vendor>.ts` (`openai`, `anthropic`, `google`, `xai`): a const object of alias → `{ rid }` plus only the flags the adapter reads. The phase that first needs a list adds it, and `model(id)` is typed from its keys. `packages/foundry-ai` is untouched.                                                                            | Duplication is clearer than one source compiled into both packages, which would couple their builds, caches and releases. Depending on `@shpitdev/foundry-ai` would install the `ai` peer.                                                               |
| Upstream code      | Port logic (prompt conversion, stream state machines), not generated schemas. Each derived file starts with `// Adapted from @effect/ai-<x> (MIT), effect@4.1.4, 82904fe.`; the MIT text is in `NOTICE`. Gemini has no Effect provider, so `internal/google-gemini/` adapts `@ai-sdk/google` (Apache-2.0) 4.0.122 and says so.                                                                 | Keeps attribution exact and auditable.                                                                                                                                                                                                                   |
| Gemini JSON output | `responseJsonSchema` from `LanguageModel.defaultCodecTransformer`. Beside function tools, the schema becomes a synthetic `json` function under `ANY` mode instead, and its call returns as the answer text, not a tool call.                                                                                                                                                                   | Live check (November 19, 2026, `gemini-3.1-flash-lite`): Foundry accepted the default schema (`anyOf`, bounds, `enum`, `$defs`) and ignored `const`, which Effect never emits. With JSON and tools, the model re-called the tool after each result.      |

## Testing approach

- `test/matrix.ts` drives both suites. A module's cells live in `test/cells/<Module>.ts`, one Effect program per cell that both suites load by module name; a row without that file stays `it.todo`. Offline, a cell runs over `FakeFoundry.replay(...fixtures)` and asserts each request (path, headers, body) and the decoded Effect AI result; live, it runs over Foundry and asserts the same result loosely. No unit tests for individual helpers unless a bug needs one.
- Language modules share their cells: `test/cells/<Module>.ts` is `languageCells(target)` from `test/capabilities.ts`, so every vendor runs the same prompts and assertions. Each recorded fixture keeps the request Foundry answered, with its non-secret headers, and the offline run must send the same requests, no more and no fewer; those golden requests pin a vendor's wire format. A target's `replay` check asserts that a reasoning first turn carries what the vendor needs sent back, so a recording without it fails instead of replacing the replay fixture.
- `tools` is two requests (tool call, then tool result and answer) with reasoning on. That exercises replay of encrypted reasoning, thinking signatures and thought signatures under `store: false`, where stateless Foundry differs most from upstream.
- Contract-only cells use fixtures Foundry cannot produce on demand, labelled synthetic: `stream-truncated` cuts a recorded `.sse` and must fail with `InvalidResponseError`, never finish as `stop`; `stream-error` replays an in-band error event; the decision `refusal` is hand-written.
- `FoundryClient`'s `error-mapping` cell runs once, for all modules: 401, 404 `LanguageModelNotAvailable`, 429 with `retry-after`, 5xx, a malformed 200 and a bodyless response.
- Fixtures are real proxy bytes in `<cell>.json`; synthetic ones live in `<cell>.synthetic.json` and replay after the recorded ones. `FOUNDRY_RECORD=1` makes the live suite rewrite each passing cell's `<cell>.json`, never a synthetic file. A fixture keeps the status, content type and body only. Recording runs only with `FOUNDRY_RECORD=1`, copies each body without delaying the reader, and scrubs the token, bearer credentials, the stack host, non-model RIDs and ID values; an ID keeps one `redacted-id-N` placeholder across the cell. Grep the fixtures for the host before committing. The three xAI fixtures in `packages/foundry-ai/src/__tests__/fixtures` seed phase 3.
- The live suite runs every cell that is not contract-only over `FetchHttpClient` against each row's live models (`pnpm run test:live:effect`). It runs under `infisical run`, which supplies `FOUNDRY_URL` and `FOUNDRY_TOKEN` after `infisical login`, and never runs in CI.
- A phase is done when its row in `test/matrix.ts` has no todos and the live suite passes for its models.

## Phases

Order: 1 → {2, 6} → {3, 4, 5, 7}. Braced phases run in parallel worktrees. A phase adds its module, its internal folder, its model list, `test/cells/<Module>.ts`, its fixtures and its budget line. From phase 2 on these are frozen, and a phase that needs one changed raises it with the coordinator first: `src/FoundryClient.ts`, `src/internal/errors.ts`, `test/matrix.ts`, `test/contract.test.ts`, `test/foundry.live.test.ts`, `test/harness.ts`, `test/FakeFoundry.ts` and `test/capabilities.ts`.

## Decision model (phase 1)

The wire has only predicate, choice and score, so there is no Locate. Settled gaps:

- A refusal without a decision name returns `Refusal` for every unanswered decision, so `decide` fails with `ContentPolicyError`; an `InvalidResponseError` would invite a retry. What the null name means is unverified.
- Foundry rejects image URLs, so a URL image fails with `InvalidUserInputError` before sending. The `image-state` cell asserts it.
- `image-state` runs under `Random.withSeed`. Core replaces each image with a UUID drawn from `Random` and the adapter sends it in the request text, so the golden request needs a fixed seed.
- `refusal` is contract-only: the only observed refusal came from a prompt the suite does not send. It asserts that `decide` fails with `ContentPolicyError` and that `decideSettled` reports `Refused` while the other answers survive.
- `wide-choice` asks one question with 20 choices. Core marks a classify or rate answer invalid unless every label has a probability; Foundry returned all 20, so the adapter fills no zeros.
- String state is sent as `input` unchanged and other state as JSON text, as upstream does; Foundry accepts the string form. The response carries `model` but no `id`.
- No client-side limit checks. `Decision.classify`, `rate` and `make` already reject fewer than two labels or levels and empty decision sets, instructions are required by type, and Foundry's HTTP 400 covers the rest as `InvalidRequestError`.

## Per-phase checklist

1. Read [the provider contract](protocols/effect-provider-contract.md) and the protocol note for the phase. Implement what the matrix cells need; treat the rest of the protocol note as reference.
2. Port from the cited upstream ranges; add the attribution header to derived files.
3. Replace the stub bodies. If the phase is the first to need a vendor's model list, add `src/internal/models/<vendor>.ts` with only the fields the adapter reads. Leave `src/internal/notImplemented.ts`; integration deletes it after phases 3–6 land.
4. Write `test/cells/<Module>.ts` (language modules: `languageCells(target)`), record fixtures with `FOUNDRY_RECORD=1 pnpm run test:live:effect`, and grep them for the stack host before committing. Build `stream-truncated` and `stream-error` by editing a copy of the recorded `stream` fixture. Check that the recorded first `tools` turn contains reasoning; models often skip it before an obvious call.
5. Set the module's budget in `scripts/check-tree-shaking.mjs` to its measured size plus about 20%.
6. Run `pnpm run verify` and `pnpm run test:live:effect`.
