# Effect AI adapters: plan

`@shpitdev/foundry-effect-ai` gives Effect AI programs the Foundry coverage `@shpitdev/foundry-ai` gives the Vercel AI SDK: OpenAI, Anthropic, Google and xAI models through Foundry's LLM proxy, addressed by catalog alias or RID. It ships as one package whose only peer dependency is `effect`, and an application that uses one vendor bundles only that vendor's code.

Release candidates publish to npm's `next` tag as phases land; phase 8 cuts the first stable release. The scaffold, guardrails and protocol notes are in place; every public function is a stub that dies with a pointer to this file.

## Decisions

| Topic              | Decision                                                                                                                                                                                                                                                                                                                                                  | Why                                                                                                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dependencies       | `effect` ^4.1.4 only. No vendor SDKs, no `@effect/ai-openai` or `@effect/ai-anthropic`.                                                                                                                                                                                                                                                                   | Effect 4 ships the AI core (`effect/ai`), HTTP client (`effect/http`) and SSE decoder (`effect/encoding/Sse`). The upstream providers add 22k–77k-line generated schema files, and there is no Effect 4 Google provider.                                 |
| Public surface     | One module per vendor and model kind, imported by subpath: `@shpitdev/foundry-effect-ai/AnthropicLanguageModel`. No root entry, no barrel.                                                                                                                                                                                                                | A barrel would pull every vendor into every bundle. This mirrors upstream Effect's deep-import style.                                                                                                                                                    |
| Module API         | `model(id)` returning `AiModel.Model`, plus `make` and `layer`, matching upstream providers. Per-model `Config` and `withConfigOverride` arrive with each implementation.                                                                                                                                                                                 | Users can swap an upstream provider for ours without restructuring their program.                                                                                                                                                                        |
| Provider namespace | The `providerName` (`foundry-openai`, `foundry-anthropic`, `foundry-google`, `foundry-xai`) is the only key for response metadata and provider options. Never augment the upstream `openai` or `anthropic` keys.                                                                                                                                          | Upstream providers augment `DecideResponseMetadata` and the `Response.*Metadata` interfaces under `openai` and `anthropic`; our shapes under the same keys fail typecheck for anyone who installs both.                                                  |
| Transport          | One `FoundryClient` service with two operations, `json` and `sse`. It owns the URL, bearer token, attribution and trace headers, and maps HTTP failures to `AiError` in `internal/errors.ts`. A request may add headers, such as `anthropic-version` or `X-Palantir-session-id`.                                                                          | Protocol-typed client methods would put every schema into the shared module.                                                                                                                                                                             |
| Wire schemas       | Hand-written `effect/Schema` codecs under `src/internal/<protocol>/`, decoding only the fields we read; unknown stream events are ignored. Requests are plain interfaces.                                                                                                                                                                                 | Foundry deviates from vendor specs in small ways (omitted `object`, extra reasoning events), so strict generated schemas fail. Upstream also hand-writes its OpenAI client schemas.                                                                      |
| Vendor quirks      | Request shaping lives in the vendor module: `store: false`, strict function tools, forced reasoning, Anthropic structured-output mode, no eager tool-input streaming.                                                                                                                                                                                     | Same rules as `packages/foundry-ai/src/providers`, driven by catalog metadata.                                                                                                                                                                           |
| Streaming          | Every language model implements both `generateText` and `streamText`.                                                                                                                                                                                                                                                                                     | `LanguageModel.make` requires both.                                                                                                                                                                                                                      |
| xAI                | `XaiLanguageModel` reuses the Responses codec, passing its xAI dialect as a value.                                                                                                                                                                                                                                                                        | Foundry serves Grok through Responses; the AI SDK adapter's `xai-compat.ts` rewrites are unnecessary with lenient decoding. Vendor branches inside `openai-responses/` would be invisible to the tree-shaking check, since both modules own that folder. |
| Build              | `tsc` emits ESM, one file per module, `sideEffects: false`.                                                                                                                                                                                                                                                                                               | Effect 4 is ESM-only; per-file output lets bundlers drop unused modules without a pure-annotation pass.                                                                                                                                                  |
| Model catalog      | The per-vendor catalogs, `realtime-models.ts`, `metadata.ts` and the model types move to `packages/foundry-catalog` (workspace source with no `package.json`), compiled into both packages (phase 0a). The all-vendor `catalog.ts` stays in `packages/foundry-ai`. Release selection and the Nx cache count `packages/foundry-catalog` as a shared input. | Depending on `@shpitdev/foundry-ai` would install the `ai` peer; a third published package would couple release lines. `catalog.ts` imports `FoundryModelNotFoundError` and would put every vendor in every bundle; lint already blocks it.              |
| Upstream code      | Port logic (prompt conversion, stream state machines), not generated schemas. Each derived file starts with `// Adapted from @effect/ai-<x> (MIT), effect@4.1.4, 82904fe.`; the MIT text is in `NOTICE`.                                                                                                                                                  | Keeps attribution exact and auditable.                                                                                                                                                                                                                   |

## Guardrails

`pnpm run verify` runs all of these for both packages; CI runs the same command.

| Check          | Command (Nx target)               | Enforces                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lint           | `foundry-effect-ai:lint`          | oxlint (`.oxlintrc.json`, strict, mirrors foundry-cli): no `any`, non-null assertions, default exports, cycles or barrels. Bans `ai`, `@ai-sdk/*`, `@effect/ai-*`, the `effect`, `effect/ai` and `effect/http` barrels, and `@shpitdev/foundry-ai`. ## Testing approach

- `test/matrix.ts` drives both suites. Each cell is one contract test using `FakeFoundry.replay(...fixtures)`, which asserts each request (path, headers, body) and the decoded Effect AI result. No unit tests for individual helpers unless a bug needs one.
- `tools` is two requests (tool call, then tool result and answer) with reasoning on. That exercises replay of encrypted reasoning, thinking signatures and thought signatures under `store: false`, where stateless Foundry differs most from upstream.
- Contract-only cells use fixtures Foundry cannot produce on demand, labelled synthetic: `stream-truncated` cuts a recorded `.sse` and must fail with `InvalidResponseError`, never finish as `stop`; `stream-error` replays an in-band error event; the decision `refusal` is hand-written.
- `FoundryClient`'s `error-mapping` cell runs once, for all modules: 401, 404 `LanguageModelNotAvailable`, 429 with `retry-after`, 5xx, a malformed 200 and a bodyless response.
- Fixtures are real proxy bytes unless labelled synthetic. Phase 1 adds `FOUNDRY_RECORD=1` to the live suite, which rewrites `test/fixtures/`. A fixture keeps the status, content type and body only. Recording scrubs the stack hostname, non-model RIDs, and request, trace and error-instance IDs; grep the fixtures for the host before committing. The three xAI fixtures in `packages/foundry-ai/src/__tests__/fixtures` seed phase 3.
- The live suite runs every cell that is not contract-only over `FetchHttpClient` against each row's live models (`pnpm run test:live:effect`). It runs under `infisical run`, which supplies `FOUNDRY_URL` and `FOUNDRY_TOKEN` after `infisical login`, and never runs in CI.
- A phase is done when its row in `test/matrix.ts` has no todos and the live suite passes for its models.

## Decision model (phase 1)

The wire has only predicate, choice and score, so there is no Locate. Settled gaps:

- A refusal without a decision name returns `Refusal` for every unanswered decision, so `decide` fails with `ContentPolicyError`; an `InvalidResponseError` would invite a retry. What the null name means is unverified.
- Foundry rejects image URLs, so a URL image fails with `InvalidUserInputError` before sending. The `image-state` cell asserts it.
- `image-state` runs under `Random.withSeed`. Core replaces each image with a UUID drawn from `Random` and the adapter sends it in the request text, so the golden request needs a fixed seed.
- `refusal` is contract-only: the only observed refusal came from a prompt the suite does not send. It asserts that `decide` fails with `ContentPolicyError` and that `decideSettled` reports `Refused` while the other answers survive.
- `wide-choice` asks one question with about 20 choices. Core marks a classify or rate answer invalid unless every label has a probability, and Foundry is verified only for three. If the wire truncates, the adapter fills zeros; record that as a decision.
- No client-side limit checks. `Decision.classify`, `rate` and `make` already reject fewer than two labels or levels and empty decision sets, instructions are required by type, and Foundry's HTTP 400 covers the rest as `InvalidRequestError`.

## Per-phase checklist

1. Read [the provider contract](protocols/effect-provider-contract.md) and the protocol note for the phase. Implement what the matrix cells need; treat the rest of the protocol note as reference.
2. Port from the cited upstream ranges; add the attribution header to derived files.
3. Replace the stub bodies. Leave `src/internal/notImplemented.ts`; integration deletes it after phases 3–6 land.
4. Record fixtures live, then replace the row's todos with contract and live tests.
5. Set the module's budget in `scripts/check-tree-shaking.mjs` to its measured size plus about 20%. A runtime import of a vendor catalog brings the whole file (minified: OpenAI 13.4 KB, Anthropic 6.1 KB, Google 4.6 KB, xAI 3.0 KB), so more than half of the 24 KB decision budget is catalog.
6. Run `pnpm run verify` and `pnpm run test:live:effect`.
