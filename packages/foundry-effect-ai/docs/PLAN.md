# Effect AI adapters: plan

`@shpitdev/foundry-effect-ai` gives Effect AI programs the Foundry coverage `@shpitdev/foundry-ai` gives the Vercel AI SDK: OpenAI, Anthropic, Google and xAI models through Foundry's LLM proxy, addressed by catalog alias or RID, plus OpenAI realtime sessions. It ships as one package whose only peer dependency is `effect`, and an application that uses one vendor bundles only that vendor's code.

All phases are done, including realtime (phase 9). This file is the design record; [the package README](../README.md) covers use, and [docs/README.md](./README.md) has the live results per model.

The upstream providers add 22k–77k-line generated schema files, and there is no Effect 4 Google provider.                                 |

No root entry, no barrel.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | A barrel would pull every vendor into every bundle. This mirrors upstream Effect's deep-import style.                                                                                                                                                    |
| Module API         | `model(id, config?)` returning `AiModel.Model`, plus `make` and `layer`, matching upstream providers. `config` holds request-wide settings under their wire names (OpenAI: `reasoning`). `withConfigOverride` waits for a cell that needs it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Users can swap an upstream provider for ours without restructuring their program.                                                                                                                                                                        |
| Provider namespace | The `providerName` (`foundry-openai`, `foundry-anthropic`, `foundry-google`, `foundry-xai`) is the only key for response metadata and provider options. Non-2xx responses fail (`filterStatusOk`) before `transformClient`, so a caller's retry or tap sees them, and the final status is checked again in case the transform returns a failed response. A request may add headers, such as `anthropic-version` or `X-Palantir-session-id`. A configured `traceParent` replaces the trace context Effect would propagate from the current span.                                                                                                                                                          | Protocol-typed client methods would put every schema into the shared module.                                                                                                                                                                             |
| Wire schemas       | Hand-written `effect/Schema` codecs under `src/internal/<protocol>/`, decoding only the fields we read; unknown stream events are ignored. Requests are plain interfaces.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Foundry deviates from vendor specs in small ways (omitted `object`, extra reasoning events), so strict generated schemas fail. Upstream also hand-writes its OpenAI client schemas.                                                                      |
| Vendor quirks      | Request shaping lives in the vendor module: `store: false`, strict function tools, forced reasoning, Anthropic structured-output mode, no eager tool-input streaming.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Same rules as `packages/foundry-ai/src/providers`, driven by flags in each vendor's model list.                                                                                                                                                          |
| Streaming          | Every language model implements both `generateText` and `streamText`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | `LanguageModel.make` requires both.                                                                                                                                                                                                                      |
| xAI                | `XaiLanguageModel` reuses the Responses codec, passing its xAI dialect as a value.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Foundry serves Grok through Responses; the AI SDK adapter's `xai-compat.ts` rewrites are unnecessary with lenient decoding. Vendor branches inside `openai-responses/` would be invisible to the tree-shaking check, since both modules own that folder. |
| Build              | `tsc` emits ESM, one file per module, `sideEffects: false`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Effect 4 is ESM-only; per-file output lets bundlers drop unused modules without a pure-annotation pass.                                                                                                                                                  |
| Model lists        | Each vendor has its own plain list in `src/internal/models/<vendor>.ts` (`openai`, `anthropic`, `google`, `xai`): a const object of alias → `{ rid }` plus only the flags the adapter reads. The phase that first needs a list adds it, and `model(id)` is typed from its keys. `packages/foundry-ai` is untouched.                                                                                                                                                                                                                                                                                                                                                                                                                            | Duplication is clearer than one source compiled into both packages, which would couple their builds, caches and releases. Depending on `@shpitdev/foundry-ai` would install the `ai` peer.                                                               |
| Upstream code      | Port logic (prompt conversion, stream state machines), not generated schemas. Each derived file starts with `// Adapted from @effect/ai-<x> (MIT), effect@4.1.4, 82904fe.`; the MIT text is in `NOTICE`. Gemini has no Effect provider, so `internal/google-gemini/` adapts `@ai-sdk/google` (Apache-2.0) 4.0.122 and says so.                                                                                                                                                                                                                                                                                                                                                                                                                 | Keeps attribution exact and auditable.                                                                                                                                                                                                                   |
| Realtime           | `OpenAiRealtime` is a scoped session over `effect/socket/Socket` on Foundry's WebSocket route, not an Effect AI service: `connect` returns typed `send` and a `Stream` of decoded server events, plus helpers that build session tools from a `Toolkit` and run its handlers. The caller passes its own token and provides `Socket.WebSocketConstructor`; `FoundryClient` stays HTTP-only. See [Realtime](#realtime-phase-9).                                                                                                                                                                                                                                                                                                                  | Effect 4.1.4 has no realtime abstraction in `effect/ai`. A realtime token must be the end user's, while a `FoundryClient` layer is app-wide and usually holds a server token.                                                                            |
| Gemini JSON output | `responseJsonSchema` from `LanguageModel.defaultCodecTransformer`. Beside tools, the schema is a synthetic `json` function under `ANY` mode, and its call is the answer text and replays as that call. Keywords outside Gemini's subset and types with no JSON form pass through unchecked; the codec still validates the answer.                                                                                                                                                                                                                                                                                                                                                                                                              | Live check (November 19, 2026, `gemini-3.1-flash-lite`): Foundry accepted the default schema (`anyOf`, bounds, `enum`, `$defs`) and ignored `const`, which Effect never emits. With JSON and tools, the model re-called the tool after each result.      |

## Testing approach

- `test/matrix.ts` drives both suites. A module's cells live in `test/cells/<Module>.ts`, one Effect program per cell that both suites load by module name; a row without that file stays `it.todo`. Offline, a cell runs over `FakeFoundry.replay(...fixtures)` and asserts each request (path, headers, body) and the decoded Effect AI result; live, it runs over Foundry and asserts the same result loosely. No unit tests for individual helpers unless a bug needs one.
- Language modules share their cells: `test/cells/<Module>.ts` is `languageCells(target)` from `test/capabilities.ts`, so every vendor runs the same prompts and assertions. Each recorded fixture keeps the request Foundry answered, with its non-secret headers, and the offline run must send the same requests, no more and no fewer; those golden requests pin a vendor's wire format. A target's `replay` check asserts that a reasoning first turn carries what the vendor needs sent back, so a recording without it fails instead of replacing the replay fixture.
- `tools` is two requests (tool call, then tool result and answer) with reasoning on. That exercises replay of encrypted reasoning, thinking signatures and thought signatures under `store: false`, where stateless Foundry differs most from upstream.
- Contract-only cells use fixtures Foundry cannot produce on demand, labelled synthetic: `stream-truncated` cuts a recorded `.sse` and must fail with `InvalidResponseError`, never finish as `stop`; `stream-error` replays an in-band error event; the decision `refusal` is hand-written.
- `FoundryClient`'s `error-mapping` cell runs once, for all modules: 401, 404 `LanguageModelNotAvailable`, 429 with `retry-after`, 5xx, a malformed 200 and a bodyless response. Its contract-only `transform-client` cell checks that a `transformClient` retry recovers from a 503, and that a failed response a transform hands back still fails.
- Fixtures are real proxy bytes in `<cell>.json`; synthetic ones live in `<cell>.synthetic.json` and replay after the recorded ones. `FOUNDRY_RECORD=1` makes the live suite rewrite each passing cell's `<cell>.json`, never a synthetic file. A fixture keeps the status, content type and body only. Recording runs only with `FOUNDRY_RECORD=1`, copies each body without delaying the reader, and scrubs the token, bearer credentials, the stack host, non-model RIDs and ID values; an ID keeps one `redacted-id-N` placeholder across the cell. Grep the fixtures for the host before committing. The three xAI fixtures in `packages/foundry-ai/src/__tests__/fixtures` seed phase 3.
- The live suite runs every cell that is not contract-only over `FetchHttpClient` against each row's live models (`pnpm run test:live:effect`). It runs under `infisical run`, which supplies `FOUNDRY_URL` and `FOUNDRY_TOKEN` after `infisical login`, and never runs in CI.
- `LIVE_MODELS` sweeps the catalog, as in `packages/foundry-ai`: `all`, provider names or catalog IDs, and an unknown token fails. A module's `cellsFor(model)` runs the shared cells on each selected model with that model's settings (thinking mode, reasoning on or off); rows without it run their default cells once. A sweep never records.

## Decision model (phase 1)

The wire has only predicate, choice and score, so there is no Locate. Settled gaps:

- A refusal without a decision name returns `Refusal` for every unanswered decision, so `decide` fails with `ContentPolicyError`; an `InvalidResponseError` would invite a retry. What the null name means is unverified.
- Foundry rejects image URLs, so a URL image fails with `InvalidUserInputError` before sending. The `image-state` cell asserts it.
- `image-state` runs under `Random.withSeed`. Core replaces each image with a UUID drawn from `Random` and the adapter sends it in the request text, so the golden request needs a fixed seed.
- `refusal` is contract-only: the only observed refusal came from a prompt the suite does not send. It asserts that `decide` fails with `ContentPolicyError` and that `decideSettled` reports `Refused` while the other answers survive.
- `wide-choice` asks one question with 20 choices. Core marks a classify or rate answer invalid unless every label has a probability; Foundry returned all 20, so the adapter fills no zeros.
- String state is sent as `input` unchanged and other state as JSON text, as upstream does; Foundry accepts the string form. The response carries `model` but no `id`.
- No client-side limit checks. `Decision.classify`, `rate` and `make` already reject fewer than two labels or levels and empty decision sets, instructions are required by type, and Foundry's HTTP 400 covers the rest as `InvalidRequestError`.

## Realtime (phase 9)

`OpenAiRealtime` gives Effect programs the realtime sessions `@shpitdev/foundry-ai/realtime` gives the AI SDK, on `gpt-realtime`, `gpt-realtime-1.5`, `gpt-realtime-2`, `gpt-realtime-2.1` and `gpt-realtime-2.1-mini`.

**Wire.** `wss://<host>/language-model-service/ws/v1/open-ai/realtime?model=<api-name>` with a `Bearer-<token>` subprotocol, speaking OpenAI's GA realtime events (`session.type: 'realtime'`, `output_modalities`, `audio.input.format`). The route takes API names, including the dot in `gpt-realtime-1.5`, not RIDs. Foundry accepts the upgrade for a bad token or an unknown model, then closes with 1008 and a reason: `ServiceException: PERMISSION_DENIED (Default:PermissionDenied)` or `LanguageModelService:ProxyModelNotFound {alias=…}` (live check, November 22, 2026, UTC).

**API.**

```ts
connect(options: { model; foundryUrl; token: Redacted; openTimeout? })
  : Effect<Session, AiError, Socket.WebSocketConstructor | Scope>
interface Session {
  send(event: ClientEvent): Effect<void, AiError>
  events: Stream<ServerEvent, AiError>
}
tools(toolkit): Effect<ReadonlyArray<FunctionTool>, AiError>   // for session.update
handleToolCalls(session, toolkit, options?): (events) => events  // runs the handlers
failOnError: (events) => events                                  // error events → AiError
```

- `connect` dials and reads up to `session.created`, so a refused token or model fails `connect` itself; `events` still starts with `session.created`. Closing the scope closes the socket with 1000.
- Auth and URL come per session, not from `FoundryClient`: the token is the caller's own Foundry token with `language-model-service:use-model`, and a browser never gets a shared server token. `foundryUrl` is the stack URL `FoundryClient` takes, but must be an HTTPS origin with no path, credentials, query or fragment, and the token must be a valid subprotocol token. Both fail with `InvalidUserInputError` before dialing. Callers provide `Socket.WebSocketConstructor`, usually `Socket.layerWebSocketConstructorGlobal` (browsers, Node 22+, Deno, Bun), so library code has no `node:*` and no global `WebSocket`.
- `send` takes client events as plain interfaces under their wire names: `session.update`, `conversation.item.create` (user `input_text` or `input_audio` messages, `function_call_output`), `response.create`, `response.cancel`, and `input_audio_buffer.append`, `.commit` and `.clear`.
- `events` decodes what the AI SDK probes use: `session.created` and `.updated`, `error`, `input_audio_buffer.committed`, `response.created` and `.done`, and the `delta` and `done` events of `response.output_text`, `response.output_audio`, `response.output_audio_transcript` and `response.function_call_arguments`. Schemas are hand-written and lenient, as in `internal/openai-responses/`: other event types are skipped, and `response.done` keeps only `message` and `function_call` output items. `events` pulls one event at a time from the socket, so a consumer that stops early loses nothing and the next run continues from there. It is for one consumer at a time.
- `handleToolCalls` passes events through. After each completed `response.done` with `function_call` items, it runs each call through `toolkit.handle`, sends the final encoded result as a `function_call_output` item, then one `response.create`. Waiting for `response.done` avoids starting a response while one is active. `tools(toolkit)` builds the session's function tools from `Tool.getJsonSchema` and the tool descriptions.

**Errors.** Socket open, read and write failures are `NetworkError`. A close with 1000 ends `events`. A 1008 close is `AuthenticationError` for Foundry's `PermissionDenied` or `Unauthorized` and `InvalidRequestError` otherwise; 1011 to 1014 are `InternalProviderError`; 1001 and 1006 are `NetworkError`; anything else is `UnknownError`. Foundry's error name and code from the close reason go under `foundry`. A frame that is not JSON, or a known event that does not decode, fails `events` with `InvalidResponseError`. `error` events are data, because the session survives them; `failOnError` maps them to `AiError` like the Responses in-band errors (quota and rate-limit codes, `invalid_request_error` as `InvalidRequestError`, otherwise `InternalProviderError`), with `code` and `type` under `foundry-openai`.

**Models.** `src/internal/models/realtime.ts` lists the five API names, with no flags. `ModelId` also takes any other string, as in the other modules, so a new realtime model works before the list knows it.

**Tests.** The `OpenAiRealtime` row has the AI SDK suite's five probes, `connect`, `text`, `tools` (through `handleToolCalls`), `audio-output` and `audio-input`, plus `error-mapping`. A realtime fixture is a list of socket sessions: the URL, the frames sent and received in order, and Foundry's close if it closed first. `test/FakeSocket.ts` replays them as a `WebSocketConstructor`: it emits received frames up to the next recorded send and waits for the client's frame, and the suite then asserts the sent frames equal the recorded ones. Live cells use `layerWebSocketConstructorGlobal`; recording wraps it and scrubs frames with the shared scrubber. `audio-input` sends the audio from the `audio-output` prompt to a fresh session, as the AI SDK suite does. The default model is `gpt-realtime-2.1`; `LIVE_MODELS` sweeps all five.

## Adding a module

1. Read [the provider contract](protocols/effect-provider-contract.md) and the protocol note. Implement what the matrix cells need; treat the rest of the note as reference.
2. Port from the cited upstream ranges; add the attribution header to derived files.
3. Add the matrix row and, if the vendor is new, `src/internal/models/<vendor>.ts` with only the fields the adapter reads, and its key in `internal/metadata.ts`.
4. Write `test/cells/<Module>.ts` (language modules: `cellsFor(model)` over `languageCells(target)`), record fixtures with `FOUNDRY_RECORD=1 pnpm run test:live:effect`, and grep them for the stack host before committing. Build `stream-truncated` and `stream-error` by editing a copy of the recorded `stream` fixture. Check that the recorded first `tools` turn contains reasoning; models often skip it before an obvious call.
5. Set the module's budget in `scripts/check-tree-shaking.mjs` to its measured size plus about 20%.
6. Run `pnpm run verify`, `pnpm run test:live:effect`, and a `LIVE_MODELS=<vendor>` sweep.
