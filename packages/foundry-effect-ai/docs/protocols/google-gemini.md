# Google Gemini: generateContent

**Routes:** POST `${foundryUrl}/api/v2/llm/proxy/google/v1/models/{rid}:generateContent` (JSON) and `…/models/{rid}:streamGenerateContent?alt=sse` (SSE). Model goes in path, not body. The SDK prefixes bare IDs with `models/`; it passes already-qualified paths through. Google public docs use `/v1beta`, not the Foundry prefix.

## Request and Prompt

- `{contents,systemInstruction?,generationConfig?,tools?,toolConfig?,safetySettings?,cachedContent?}`. `generationConfig`: optional `maxOutputTokens`, `temperature`, `topP`, `topK`, `stopSequences`, `seed`, `thinkingConfig:{includeThoughts?,thinkingBudget?|thinkingLevel?}` (budget vs. level is model-specific). Don't send Vertex-only settings. Structured output: `responseMimeType:"application/json"` plus `responseJsonSchema` (don't also send `responseSchema`); derive JSON schema with a matching Effect codec and use Gemini's subset. Port SDK's recursive `const`→singleton `enum`; reject unsupported schemas rather than silently removing required semantics.
- Leading system → `systemInstruction:{parts:[{text},…]}`; reject interleaved system instructions. User → `{role:"user",parts}` with `{text}`, `{inlineData:{mimeType,data:base64}}` or `{fileData:{mimeType,fileUri}}` for supported remote/file-store URIs. Normalize data URLs to bare base64. Foundry hosted/file-store URI support **UNVERIFIED**.
- Assistant → `role:"model"`, text parts; reasoning `{text,thought:true}` when replayable; attach the original opaque `thoughtSignature` to the exact part that carried it (including function calls). Tool call `{functionCall:{name,args,id?}}` with object args. Keep part order, especially the first signature in parallel calls. Preserve the wire ID if provided; generate a local Effect ID if absent and keep wire-vs-local distinction. Do not fabricate signatures to mask dropped history.
- Tool results → `role:"user"` with `{functionResponse:{name,id?,response:{name,content}}}` or `{name,error}` inside `response` for a failure; echo wire ID if available. Object `response` is required; follow peer serialization for scalar/text and JSON. Prefer `modelOutput`; multimodal `functionResponse.parts` is model-specific and Foundry support **UNVERIFIED**. Local approvals don't become wire parts.
- `tools:[{functionDeclarations:[{name,description?,parametersJsonSchema}]}]`; `toolConfig.functionCallingConfig.mode`: `AUTO` / `NONE` / `ANY` for auto / none / required; named → `ANY` + `allowedFunctionNames:[name]`; subset → restrict declarations and optionally allowlist. `VALIDATED` is the peer's strict-auto mode, not needed by default. Combining native JSON with function tools is model/choice gated; current peer uses a synthetic JSON tool on certain models or forced choices. If implemented, convert the synthetic call to JSON text, not a Toolkit call. Don't assume the RID activates peer capability heuristics.

## Response and stream

- JSON `{responseId?,modelVersion?,candidates?,promptFeedback?,usageMetadata?}`. Emit metadata, then ordered `candidates[0].content.parts`: `{text,thought:true}`→reasoning, ordinary text→text, `{functionCall:{id?,name,args}}`→tool-call (object, default `{}` only for valid empty input). Keep `thoughtSignature` in metadata for replay, including signature-only fragments. If enabling provider tools, pair `toolCall`/`toolResponse` by wire ID (or `codeExecutionResult` with its preceding `executableCode` part) and mark both `providerExecuted:true`. Otherwise keep those features out of scope.

| SSE `data:` payload                                   | Effect parts / state                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First `responseId` / `modelVersion`, `promptFeedback` | Metadata once; confirmed block reason can terminate without candidates. Ignore `BLOCK_REASON_UNSPECIFIED` as a signal.                                                                                                                                                                                                                                                                                  |
| Ordered `candidates[0].content.parts[]`               | Open text/reasoning on first delta, close on type switch, tool boundary or end; attach signatures without emitting them as text.                                                                                                                                                                                                                                                                        |
| `functionCall`                                        | Gemini API normally sends complete args object in one part: params start, JSON delta, params end, parsed/normalized call, in order. `partialArgs[{jsonPath,…,willContinue?}]` is the peer's Vertex path, not string concatenation: update JSON path values, append continued strings, finalize when no call/arg continuation. Don't request this flag; Foundry partial-argument support **UNVERIFIED**. |
| `finishReason`, `usageMetadata`, EOF                  | Capture reason after calls are processed; keep latest cumulative usage snapshot (even on a usage-only chunk). Close blocks and emit one finish on clean EOF with reason or confirmed block, not on first reason; no `[DONE]` required. Missing completion signal is interrupted, not `stop`.                                                                                                            |

- Finish: `STOP`→`tool-calls` if local calls, else `stop`; `MAX_TOKENS`→`length`; safety/blocklist/prohibited-content/SPII/recitation/image-safety → `content-filter`; `MALFORMED_FUNCTION_CALL`→`error` or typed tool validation failure. Preserve unknown reason. Gemini 4 `CONTINUATION` auto-resubmit is outside lean scope; if seen, report `length`, not `stop` (Foundry continuation-token acceptance **UNVERIFIED**).
- Usage: input total=`promptTokenCount + toolUsePromptTokenCount`, uncached=total−`cachedContentTokenCount`; text=`candidatesTokenCount`, reasoning=`thoughtsTokenCount`, output total=text+reasoning. Keep `totalTokenCount` and raw metadata for diagnostics; absent usage is unknown, not zero.
- Errors: `{error:{code?,status?,message,details?}}` on HTTP/SSE; use HTTP/embedded numeric status or convert RPC status (`RESOURCE_EXHAUSTED`→429, `UNAUTHENTICATED`→401, `PERMISSION_DENIED`→403, `INVALID_ARGUMENT`/`FAILED_PRECONDITION`→400, `UNAVAILABLE`→503). Use shared typed mapper, distinguish explicit exhausted quota from throttling, retain safe hints. Malformed event/JSON → `InvalidResponseError`; confirmed prompt block is content-filter, not a malformed empty result.

## Foundry specifics

- `packages/foundry-ai/src/providers/google.ts:19–45,56–77`, `models/catalog.ts:53–60`, `packages/foundry-catalog/src/google-models.ts:4–159`: aliases resolve to RIDs (e.g. `gemini-3.1-pro`→`ri.language-model-service..language-model.gemini-3-1-pro`), unknown inputs pass through. Use `Authorization: Bearer <token>` from the start; never set `x-goog-api-key`. Forward optional `attribution`, `traceParent`, `traceState`. Only language via this wrapper; no Google embedding/image route exposed. Catalog hints aren't wire capabilities.
- Repo sweep (`packages/foundry-ai/docs/README.md:138`) saw two Gemini JSON+tools cases return no output. Foundry `cachedContent`, strict `VALIDATED`, and newer beta-only fields **UNVERIFIED**; expose only proven options by default, no Vertex path or automatic beta fallback.
