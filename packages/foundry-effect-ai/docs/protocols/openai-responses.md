# OpenAI Responses (OpenAI and xAI)

**Routes:** POST `${foundryUrl}/api/v2/llm/proxy/openai/v1/responses` or `${foundryUrl}/api/v2/llm/proxy/xai/v1/responses`. JSON body; JSON response or SSE with `stream:true`. See the [shared Effect contract](effect-provider-contract.md).

## Request and Prompt

- Send `model`, `input`, `store:false`; optionally `max_output_tokens`, supported `temperature`/`top_p`, `reasoning:{effort?,summary?}`, `include`, `tools`, `tool_choice`, `text:{format}`. Replay the full prompt; omit `previous_response_id`, conversation and stored item references in the lean adapter (their validity with Foundry `store:false` is **UNVERIFIED**).
- OpenAI system → `{role:"system"|"developer",content:[{type:"input_text",text}]}` (`developer` when reasoning); xAI uses `system`. User → `role:"user"` + `input_text`/`input_image` (`image_url` HTTP(S) or data URL; `detail` where supported); OpenAI PDF → `input_file` with URL or base64 data URL + filename. Foundry file IDs/URL and PDF support per route **UNVERIFIED**; don't infer from upstream codecs.
- OpenAI assistant text → message with `output_text`; xAI → `{role:"assistant",content: text}` without `id`. Assistant reasoning → `type:"reasoning"` with item `id`, `summary:[{type:"summary_text",text}]`, optional `encrypted_content`; don't replay plain reasoning lacking wire metadata. Request `include:["reasoning.encrypted_content"]` for stateless OpenAI reasoning and xAI's `store:false` path. Keep reasoning and function item IDs separate from function `call_id`.
- Assistant local tool-call → `{type:"function_call",call_id,name,arguments: JSON.stringify(params),id?}` (xAI peer supplies ID/status). Tool result → `{type:"function_call_output",call_id,output}`; prefer `modelOutput` (input part array where supported), else string or JSON string of `result`. No standalone approval item or server-tool replay in the lean function-only adapter.
- Function definitions are flat `{type:"function",name,description?,parameters,strict}`; choice `auto`/`none`/`required` or `{type:"function",name}`; `oneOf` filters tools then selects mode. JSON output: `text.format:{type:"json_schema",name,schema,strict:true,description?}` via `toCodecOpenAI`. Use the strict codec for strict tool schema/params too; xAI peer structured output sets `strict:true`, distinct from Foundry OpenAI's function-tool default.

## Response and stream

- JSON: metadata from `id`, `model`, `created_at` (Unix seconds). Traverse `output` in order: message `output_text` → text; refusal → metadata (not JSON text); reasoning summary → reasoning with item ID/encrypted content even for empty summaries; function call → `tool-call` with `id=call_id`, name and securely parsed args. Local results come from Toolkit, not from a Responses function-call item. Provider-native calls/results are separate typed items, not local calls; defer unless explicitly supported.

| SSE JSON `type`                                                                                                                                | Effect parts / state                                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `response.created`, `response.in_progress`                                                                                                     | Emit metadata once when available; progress is not a finish.                                                                                                                                                                                                                                        |
| `response.output_item.added` / `.done` (message), `response.output_text.delta`                                                                 | `text-start` / `text-end` for item ID; forward deltas, don't replay final full text. Use content index too if supporting multiple text blocks per item; preserve annotations if consumed.                                                                                                           |
| `response.output_item.added` / `.done` (reasoning), `response.reasoning_summary_part.added` / `.done`, `response.reasoning_summary_text.delta` | Start/delta/end by `(item_id,summary_index)`; open lazily if start is missing, dedupe starts. Gather item/encrypted metadata, attach at end; keep the last summary open until item done for final ciphertext. xAI can also send `response.reasoning_text.delta`/`.done`; `.done` is not extra text. |
| `response.output_item.added` (function), `response.function_call_arguments.delta`                                                              | Track by `output_index`/item ID; emit params start with `call_id`, append raw argument fragments and emit deltas.                                                                                                                                                                                   |
| `response.function_call_arguments.done` / `response.output_item.done` (function)                                                               | Prefer authoritative full `arguments`, buffer only as fallback. Emit params end then exactly one parsed call. Effect OpenAI settles at args done, with item done fallback; native xAI waits for item done.                                                                                          |
| `response.completed`, `response.incomplete`, xAI `response.done`                                                                               | Close open blocks, capture usage and emit one finish; don't append terminal full output again. `max_output_tokens` → `length`, `content_filter` → `content-filter`, otherwise calls → `tool-calls` or completed → `stop`; preserve unknown raw reason.                                              |
| `error`, `response.failed`                                                                                                                     | Terminal provider error; upstream emits error data, and on `failed` also finish `error` with any usage. Apply the shared failure policy.                                                                                                                                                            |

- Usage: `input_tokens` total, subtract `input_tokens_details.cached_tokens` for uncached, optional `cache_write_tokens`; `output_tokens` total, subtract `output_tokens_details.reasoning_tokens` for text. xAI peer treats `input_tokens` as uncached if cached count exceeds it, otherwise as inclusive. Missing usage → unknown counts.
- Errors: decode OpenAI-style `{error:{message,type?,code?,param?}}` and flat/nested SSE errors; handle failed status even on 2xx. Classify quota (`insufficient_quota` / `billing_insufficient_balance`) separately from 429 throttling; preserve request ID and retry hints. Bad SSE/JSON envelope → `InvalidResponseError`; bad function arguments → `ToolParameterValidationError`. Treat optional `data: [DONE]` as a framing sentinel, not a replacement for the terminal response; early EOF is not `stop`. Skip genuinely unknown event types, not malformed required payloads.

## Foundry specifics

- Bearer token + optional `attribution`, `traceParent`, `traceState`; alias→RID, raw unknown target passthrough. `providers/openai.ts:39–69,113–159`, `models/catalog.ts:33–60`, `packages/foundry-catalog/src/openai-models.ts:580–588`: reject `store:true`, force `false`, default `strict:true` only when unset; default `forceReasoning:true` for known reasoning aliases **or** RIDs (honor explicit override). This is a local switch, not a wire field: select developer role and suppress unsupported sampling (peer has model/effort exceptions). Don't apply the upstream heuristic to opaque RIDs. Realtime targets are separate.
- `providers/xai.ts:21–67`, `packages/foundry-catalog/src/xai-models.ts:5–106`: Grok defaults to Responses; rejects `store:true`, forces `false`; known non-xAI targets rejected. Use the `foundry-xai` option namespace (PLAN.md, Provider namespace). `providers/xai-compat.ts:3–34,41–94`: strip only assistant message ID; preserve tool/reasoning IDs. Accept omitted `object` as `response`; on SSE also accept omitted `response.output` as `[]` for created/in-progress. Normalize only missing values (not null/invalid) for created/in-progress/completed/done or encode that tolerance directly. Existing fetch rewrite is Responses-only and drops content length/encoding after rewriting successful bodies.
- Repo sweep (`docs/README.md:135–137`) saw proxy `response.reasoning_summary_part.added` fail AI SDK validation for OpenAI; exact mismatched fields **UNVERIFIED**. Decode only consumed fields; capture a real fixture before making a required consumed key optional. xAI reasoning stream start events were observed in the same sweep.
