# Anthropic Messages

**Route:** POST `${foundryUrl}/api/v2/llm/proxy/anthropic/v1/messages`. Bearer auth, `anthropic-version: 2023-06-01`, JSON body; add `stream:true` for SSE. Don't append another `/v1` or copy the generated beta client URL blindly.

## Request and Prompt

- `{model,max_tokens,messages,system?,tools?,tool_choice?,thinking?,output_config?,stream?}`; optional supported `temperature`, `top_p`, `top_k`, `stop_sequences`. `max_tokens` is required; use an explicit supported budget. Thinking: `thinking:{type:"enabled",budget_tokens}` or `thinking:{type:"adaptive"}` where supported, optional `output_config.effort`; do not force tools where thinking/model forbids it.
- System → top-level `system` text blocks; merge leading system messages. Mid-history system only behind explicit capability (Foundry support **UNVERIFIED**). User → `role:"user"`, text/image/document blocks. File source: `{type:"url",url}` or `{type:"base64",media_type,data}`; PDF/plain-text documents use `type:"document"`, with `type:"text"` source for inline plain text. Supported media/URL combinations beyond tested inputs **UNVERIFIED**. Optional `cache_control:{type:"ephemeral"}` belongs on applicable blocks, not as a role.
- Assistant → text, `{type:"thinking",thinking,signature}`, `{type:"redacted_thinking",data}`, `{type:"tool_use",id,name,input}` (args object, not string). Preserve signed/redacted blocks verbatim in order when replaying; don't invent signatures. Trim trailing text whitespace on a final assistant prefill if supported. Group consecutive assistant messages and user/tool messages as appropriate.
- Local tool result → **user** block `{type:"tool_result",tool_use_id:id,content,is_error:isFailure}` before other user content in that turn. `modelOutput` wins over string/JSON `result`. Approval parts do not become wire blocks. Provider-defined calls/results require separate block codecs and matching IDs; don't send them as local tool results.
- Custom tool `{name,description?,input_schema,strict?}`; `tool_choice:{type:"auto"|"any"|"none"}` (`required` → `any`) or `{type:"tool",name}`. Alternatively omit tools/choice for none; `oneOf` filters definitions. `disable_parallel_tool_use` goes in choice when supported.
- JSON output: `toCodecAnthropic` for shared decode. Native → `output_config.format:{type:"json_schema",schema}`. JSON-tool fallback → synthetic schema tool, disable parallel use, return its input as the **only structured text**, not an executable tool. For JSON-only, force the synthetic tool (Effect reference); with application tools, the Foundry-tested peer keeps eligible tools + synthetic and uses `any` where forced tool use is allowed. Don't classify a genuine tool as synthetic merely by name; track the injected name/mode. Retain actual tool calls for subsequent turns, and don't concatenate explanatory text into the JSON result. Native can retain real tools without this shim.

## Response and stream

- JSON: `id`/`model` → metadata; ordered `content` text→text, thinking→reasoning, redacted thinking→empty reasoning with opaque-data metadata, `tool_use`→call (or synthetic JSON text). Real provider tool results (`*_tool_result` paired with `server_tool_use`, if enabled) emit `tool-result` with matching ID and `providerExecuted:true`. Local results are produced by Toolkit.

| SSE payload `type` (named events) | Effect parts / state                                                                                                                                                                                                                                         |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `message_start`                   | Emit metadata; store initial usage. Handle prepopulated content if present (upstream handles prepopulated tool calls).                                                                                                                                       |
| `content_block_start`             | Track by `index`; text/reasoning start with stable ID, preserve initial text/thinking if nonempty; redacted block carries data. Tool start uses `tool_use.id`, `name`; seed initial object if present, not placeholder `{}` ahead of deltas.                 |
| `content_block_delta`             | `text_delta.text`, `thinking_delta.thinking` → deltas; `signature_delta.signature` → reasoning metadata, not displayed text; `input_json_delta.partial_json` → append raw fragments and emit params delta; `citations_delta` → source/metadata if supported. |
| `content_block_stop`              | End text/reasoning; tool → securely parse complete JSON (or initial input / `{}`), params end then one call. In synthetic JSON mode translate to text rather than emitting synthetic call.                                                                   |
| `message_delta`, `message_stop`   | Remember `delta.stop_reason`/`stop_sequence` and merge cumulative usage fields from delta (overwrite, don't sum); emit one finish at stop. Ignore `ping`; `error` is a failure, not a normal stop.                                                           |

- Finish: `end_turn`/`stop_sequence`→`stop`, `tool_use`→`tool-calls` unless only structured JSON tool→`stop`, `max_tokens`/`model_context_window_exceeded`→`length`, `pause_turn`→`pause`, `refusal`→`content-filter`. Input uncached=`input_tokens`; total adds `cache_read_input_tokens` and `cache_creation_input_tokens`; `output_tokens` total (no text/reasoning split). Retain raw usage/stop reason if useful.
- Errors: Anthropic `{type:"error",error:{type,message},request_id?}` on HTTP or SSE. Map `overloaded_error`/529 and 5xx → `InternalProviderError`; 429/`rate_limit_error` → `RateLimitError` with retry hints; auth/input via shared mapper. Bad event/block → `InvalidResponseError`; bad accumulated tool args → `ToolParameterValidationError`; no `message_stop` after valid blocks isn't a successful completion.
