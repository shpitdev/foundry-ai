# Effect AI provider contract (4.1.4)

Implement with `effect` only. Imports: `effect/ai`, `effect/http`, `effect/encoding/Sse`; upstream providers and installed AI SDKs are wire references, not dependencies. Citations below are relative to Effect checkout `82904fe` unless prefixed `packages/foundry-ai/`.

## LanguageModel and request options
- `LanguageModel.make({generateText,streamText,codecTransformer?,supportsSystemMessagesInHistory?})` returns `Effect<LanguageModel>`. Hooks receive the same `LanguageModel.ProviderOptions`: `generateText` → `Effect<Array<Response.PartEncoded>,AiError.AiError,IdGenerator>`; `streamText` → `Stream<Response.StreamPartEncoded,AiError.AiError,IdGenerator>`. Capture HTTP/config services when constructing the model; the hooks don't expose arbitrary required services. Use `IdGenerator` for absent IDs. Optional system-history support is an `Effect<boolean>`.
- Hook input: normalized `prompt:Prompt.Prompt`, `tools:ReadonlyArray<Tool.Any>`, `toolChoice`, `responseFormat`, tracing `span`, `previousResponseId`, `incrementalPrompt`, `incrementalFallback?`, `toolCallValidation?:"strict"|"deferred"`. No free-form AI SDK-style provider options or common sampling controls here: use model config / scoped context overrides for request-wide settings; Prompt `.options` and Tool annotations carry part/tool settings. Use full `prompt` for stateless Foundry, not the incremental fields.
- Toolkit supplies schemas and handlers. `auto` / `none` / `required` / `{tool:name}` / `{oneOf:[…],mode?:"auto"|"required"}`: core prefilters tools for `oneOf`; still encode the choice and validate unsupported configurations. No Toolkit generally means empty tools and `none`. Use `Tool.getDescription`, `Tool.getStrictMode`, `Tool.getJsonSchema` or provider-transformed `parametersSchema`; handle explicit dynamic tool schemas. Use `Tool.NameMapper` for provider-defined names. Unknown names in strict mode → `ToolNotFoundError`; defer undeclared local calls with untouched parsed params only when requested. Don't execute handlers in the adapter: core resolves local calls (unless disabled), handles approvals and inserts results. `providerExecuted:true` prevents local execution. Multi-turn orchestration belongs to `Chat`/caller, not the transport hook.
- `responseFormat` is `{type:"text"}` or `{type:"json",objectName,schema}`. `generateObject` calls the same generate hook; hook receives the **original** schema, derives the wire JSON schema, and returns JSON as `text` part(s). Register the same `codecTransformer` for core to decode those joined text parts. Transformers return `{codec,jsonSchema}`: `OpenAiStructuredOutput.toCodecOpenAI` for Responses/Chat, `AnthropicStructuredOutput.toCodecAnthropic` for Messages; Gemini use default or matching Gemini-specific schema transform. Don't emit an object part. For strict tools whose wire codec changes the encoded shape, decode provider-transformed args and re-encode for the original JSON schema before emitting a call; Toolkit owns final validation and tool failure behavior. Do not just emit a JSON string as `params`.

## Prompt and response shape
- `Prompt.make` normalizes `content`: `system` has string text; `user` has `text`/`file`; `assistant` has `text`, `file`, `reasoning`, `tool-call`, `tool-result`, `tool-approval-request`; `tool` has `tool-result` and `tool-approval-response`. Files carry `mediaType`, `fileName?`, `data:string|Uint8Array|URL`. Call `{id,name,params,providerExecuted}`; result `{id,name,result,isFailure,providerExecuted,modelOutput?}` (`modelOutput`: text/file parts preferred over serialized result). Encode only supported wire parts; approvals are usually local. `Prompt.fromResponseParts` round-trips response metadata as Prompt `.options` and assembles streaming blocks on their end events.

| Encoded response part | Contract |
|---|---|
| `text`, `reasoning` | Non-streaming, `text:string`; preserve opaque replay metadata under a stable provider namespace. |
| `text-start/delta/end`, `reasoning-start/delta/end` | Streaming only: stable `id`, delta carries `delta:string`. Start before any delta and end once. Use distinct IDs per logical block; carry signature/ciphertext in metadata, not visible text. |
| `tool-params-start/delta/end` | Streaming only: `id`; start also `name`, optional `providerExecuted`; delta `delta:string`; end before the completed call. |
| `tool-call` | Both: `{id,name,params,providerExecuted?}`. Use toolkit name, parsed encoded params, stable correlation ID. |
| `tool-result` | Both: `{id,name,result,isFailure,providerExecuted?,modelOutput?}`. Emit only for supported provider-executed tools; `preliminary?` is for framework streaming handlers. Local tools' results come from core. |
| `response-metadata` | Both, once when available: optional `id`, `modelId`, ISO UTC `timestamp` (encoded string, not `Date`). |
| `finish` | Both: one terminal `{reason,usage,response?}` after content/calls. Reasons: `stop`, `length`, `content-filter`, `tool-calls`, `pause`, `error`, `other`, `unknown`. `usage` is **not** its own part: `{inputTokens:{total?,uncached?,cacheRead?,cacheWrite?},outputTokens:{total?,text?,reasoning?}}`. Use undefined/omit for unknown, not invented zeros. Optional HTTP status/headers and JSON-safe provider metadata. |
| `error` | Streaming data only: `{error:unknown}`; **not** non-streaming `Response.Part`. Distinct from typed stream failure. |

- Both unions also support `file`, `source` (URL/document), `tool-approval-request` as needed. `metadata` is a JSON-compatible namespaced record (may omit on encoded parts). Non-streaming: emit whole text/reasoning, not deltas even though the encoded alias admits some; runtime `Response.Part` decoder is narrower. Don't copy Vercel `tool-input-*`, `raw`, or `stream-start` parts into Effect.

## HTTP, SSE and AiError
- Build a shared authenticated `HttpClient` boundary using `HttpClientRequest` and `filterStatusOk`; inspect JSON via schema, SSE via UTF-8 `Stream.decodeText` → `Sse.decode` / `decodeDataSchema`. Dispatch on payload type or protocol sentinel, not transport chunk boundaries. Keep bounded event/argument buffers, map `SseError`/retry directives explicitly, close resources on interruption, never silently restart a partial generation. A valid terminal event decides success; truncation is not `stop`.
- `AiError.make({module,method,reason})` wraps semantic reasons; `reasonFromHttpStatus` is a minimal fallback. Transport → `NetworkError`; 401/403 → `AuthenticationError` (`InvalidKey`/`InsufficientPermissions` as applicable); 400/404/409/422 when applicable → `InvalidRequestError`; explicit billing/exhaustion (e.g. OpenAI 402 or quota-coded 429) → `QuotaExhaustedError`; ordinary 429 → `RateLimitError` with `retryAfter`; 5xx/overload → `InternalProviderError`; otherwise `UnknownError`. Keep safe wire codes, request IDs, HTTP context; redact auth/key headers and avoid logging prompt/body by default.
- Schema/SSE protocol mismatch or truncated stream → `InvalidResponseError`; invalid normalized output → `InvalidOutputError`; caller-side invalid modality/config → `InvalidUserInputError` or `ToolConfigurationError`; invalid argument JSON → `ToolParameterValidationError`; unsupported output schema → `UnsupportedSchemaError`; missing/invalid JSON text for object decode → core `StructuredOutputError`. Refusals/filters with a valid response use `content-filter` and metadata where appropriate, or `ContentPolicyError` for a refused operation.
- Recommended consistent policy: terminal error envelope (including HTTP 200 with error JSON/SSE) fails the hook via typed `AiError`. Upstream Responses/Messages also demonstrate in-band `error` parts, sometimes followed by finish `error`; if opting for that shape preserve the failure, don't silently emit successful `stop`. Non-streaming always uses the effect failure channel for transport/provider errors.

## Decision, embedding and layer
- `DecisionModel.make({decide,probabilityPrecision?,supportsImages?,supportsLocate?})` → `Effect<DecisionModel>`; `decide({state,decisions,images?})` → `Effect<ProviderResponse,AiError.AiError>` with keyed `{answers,usage:{inputTokens,outputTokens},id?,modelId?,metadata?}`. Answers are `Classify`, `Rate`, `Probability`, `Refusal` or (only if opted in) `Locate`. Core encodes input, extracts `reference`/`path` image entries, validates answers and builds `decide`/`decideSettled`. See [Decisions](openai-decisions.md) for the Foundry route.
- `EmbeddingModel.make({embedMany,batchKey?})` → `Effect<EmbeddingModel>`; hook `embedMany({inputs})` → `Effect<{results:number[][],usage:{inputTokens:number|undefined}},AiError.AiError>`. Exact input order/count, finite vectors. Optional `batchKey(context)` separates effective configs for batched single `embed`; core short-circuits empty batches. For Foundry only OpenAI is exposed: POST `${foundryUrl}/api/v2/llm/proxy/openai/v1/embeddings`, `{model,input:inputs,encoding_format:"float",dimensions?}` where dimensions supported. Decode `data[{index,embedding}]`, reject duplicate/missing/out-of-range indexes, reorder, read `usage.prompt_tokens`. The three catalog embedding targets are literal `text-embedding-*` names, not language RIDs (`packages/foundry-ai/src/models/openai-models.ts:510–553`, `packages/foundry-ai/src/providers/openai.ts:77–80`). The installed peer sends `float` (`node_modules/@ai-sdk/openai/src/embedding/openai-embedding-model.ts:81–103`); the repo sweep passed all three targets. Foundry limits on batch size and dimensions are **UNVERIFIED** here.
- `AiModel` is the providers' **import alias** for `effect/ai/Model`, exported as `Model` from `effect/ai`. Construct `Model.make(providerId, publicModelName, Layer.effect(LanguageModel.LanguageModel, makeService))` (same pattern for Decision/Embedding). Layer error type is `never`; separate setup failures if needed. Provide it with `Effect.provide`; it supplies `Model.ProviderName` and `Model.ModelName`. Resolve aliases independently for the wire target. `captureRequirements` captures the current context for later provision if needed.
- Foundry shared client: `${foundryUrl}/api/v2/llm/proxy/{openai,anthropic,google,xai}/v1`, Bearer, optional trimmed `attribution` (from `attributionRid`), `traceParent`/`traceState` (HTTP names case-insensitive). Mirror config validation (`packages/foundry-ai/src/config.ts:20–87`); avoid overriding user trace context inadvertently. Known alias→catalog RID, known RID→itself, unknown target passthrough (`packages/foundry-ai/src/models/catalog.ts:20–47`); use known metadata rather than prefix checks. Per-route differences are in the wire contracts.
