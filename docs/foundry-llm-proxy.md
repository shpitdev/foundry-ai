# Foundry LLM proxy

Foundry exposes selected parts of the OpenAI, Anthropic, Google, and xAI APIs. A model appearing in Foundry's catalog does not mean it can use every proxy route. These checks used one enrollment; access and serving backends can differ. For per-model streaming, tools, JSON, and image results, see [AI SDK test status](../packages/foundry-ai/docs/README.md) and [Effect AI test status](../packages/foundry-effect-ai/docs/README.md).

## Behavior to account for

- **Stored responses — documented in the [AI SDK notes](../packages/foundry-ai/docs/README.md#model-routing), reviewed Nov 22.** The OpenAI and xAI adapters reject `store: true`. Send `store: false` on Responses and replay history, including returned reasoning items.
- **Chat streams — measured Nov 22.** Streams end without `[DONE]`. With `stream_options.include_usage: true`, the four tested open-weight Chat models sent a final usage chunk with `choices: []`.
- **Parallel tools on Chat — measured Nov 22.** DeepSeek, Nemotron, Qwen, and Kimi rejected the explicit `parallel_tool_calls` field, but each returned two tool calls in one response with the field omitted.
- **Image input on Chat — measured Nov 22.** The tested Bedrock-served DeepSeek, Nemotron, and Qwen models rejected images. Kimi accepted the test image; do not infer vision support from the route.
- **Reasoning tags on Chat — measured Nov 22.** With `reasoning_effort: "high"`, DeepSeek, Nemotron, and Qwen put `<reasoning>` tags in ordinary content. That broke standalone JSON parsing in the tested decoders.
- **Reasoning effort on DeepSeek and Qwen3 235B — measured Nov 22.** With `reasoning_effort: "high"`, DeepSeek V3.2 often puts its whole answer inside the reasoning span and returns no answer text. Qwen3 235B A22B 2507, an instruct model, did not answer within 90 seconds with `"high"` but answered in under a second without it or with `"none"`.
- **Kimi reasoning replay — measured Nov 22.** Kimi K3.1 emits `reasoning_content` separately on messages and stream deltas. Foundry rejects that field on replayed assistant messages; omitting it lets tool loops finish.
- **Gemma reasoning — measured Nov 22.** No reasoning control was verified. Neither the Responses `reasoning` option nor a `<|think|>` instruction produced reasoning items or nonzero reasoning usage.
- **GPT-6.2 reasoning replay — [documented][provider guide], reviewed Nov 22.** Editing or inserting earlier items can discard replayed reasoning with `prefix_mismatch`. Append new items instead. Foundry may omit `input_transformations`, so its absence does not show that reasoning was retained.
- **Prompt caching on Decisions — measured Nov 19.** Foundry rejected `prompt_cache_key` and `prompt_cache_options` with 400, but a repeated prefix still hit the implicit cache.
- **Session affinity — [documented][provider guide], reviewed Nov 22.** Messages, OpenAI Chat, and OpenAI Responses accept the optional `X-Palantir-session-id` header. Use an opaque value shorter than 256 characters only for requests sharing a prefix. Affinity is best-effort and expires.
- **Realtime authentication — [documented][realtime guide], checked Nov 22.** Pass the caller's Foundry OAuth token with scope `language-model-service:use-model` in the `Bearer-<token>` WebSocket subprotocol. Use the model's API name, not its RID. Never give browsers a shared server token.
- **Realtime close reasons — [measured Nov 22](../packages/foundry-effect-ai/docs/PLAN.md#realtime-phase-9).** A bad token or unknown model can upgrade successfully, then close with code `1008` and `Default:PermissionDenied` or `LanguageModelService:ProxyModelNotFound` respectively. Wait for `session.created` before treating the connection as ready.
